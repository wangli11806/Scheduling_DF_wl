# 测试数据安全规范

## 规则

**涉及数据库操作的功能验证时，只允许操作测试数据。测试结束后必须自动清理，严禁删除或修改用户的真实生产数据。**

## 测试数据命名规范

创建的测试数据必须带有明显标记，便于区分和清理：

- **员工名**：以 `测试_` 或 `TEST_` 开头，如 `测试_张三`、`TEST_Li`
- **班次名**：以 `测试_` 开头，如 `测试_临时班`
- **其他实体**：同样前缀，确保一眼能识别

## 测试流程

1. 创建测试数据（带 `测试_` 前缀标记）
2. 执行功能验证
3. 验证完成后**立即**清理所有测试数据（DELETE WHERE name LIKE '测试_%' 等）
4. 向用户报告：创建了哪些测试数据、验证了什么功能、清理结果

## 严禁事项

- **绝对禁止** 删除/修改用户真实数据（无 `测试_` 前缀的数据）
- **绝对禁止** 在测试中使用真实员工/班次/排班数据做实验
- **绝对禁止** 执行 `DROP TABLE`、`DELETE FROM table`（不带 WHERE 条件）
- 批量操作前必须先 `SELECT` 确认影响范围

## 历史教训

曾有一次在验证功能时误删了用户的真实数据，用户不得不手动恢复。此后必须严格遵守测试数据隔离原则。
